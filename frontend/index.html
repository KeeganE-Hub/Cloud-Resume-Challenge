How it's built

Technical Breakdown

A walkthrough of every service this project uses, what each one is actually doing, and how the pieces connect to each other.

Views: …

This number updates live, with no page refresh. A DynamoDB Stream fires every time it changes, which triggers a Lambda function that pushes the new value out to every open tab over a WebSocket connection — open this page in two tabs and watch it update in both.

Frontend delivery

Getting the site to a browser

S3
Stores the actual HTML, CSS, JS, and image files for the site. Nothing reads from it directly, though — CloudFront sits in front of it as the CDN and is the only thing allowed to read from the bucket, via Origin Access Control, so every real visitor request flows through CloudFront first.
CloudFront
The CDN that actually serves the site to visitors — it caches content at edge locations worldwide, handles HTTPS using the certificate from ACM, and pulls from the S3 bucket as its origin. Route 53 is what points the domain at this distribution in the first place.
Route 53
AWS's DNS service — this is where the domain was registered, and it's what resolves the domain name to the CloudFront distribution, so a visitor typing the URL actually ends up routed to CloudFront, not S3 directly.
Certificate Manager (ACM)
Issues the free TLS certificate that CloudFront uses to serve everything over HTTPS. Requested specifically in us-east-1, since that's a requirement for any certificate used with CloudFront regardless of where the rest of the stack lives.

The visitor counter

Where the number comes from

API Gateway
The entry point the browser's WebSocket connection actually talks to. It routes $connect and $disconnect events to DBUpdater, and it's also what DBStreamProcessor calls back into to push live count updates out to every open connection.
Lambda
Runs the actual counter logic. DBUpdater handles new connections and disconnections coming from API Gateway; DBStreamProcessor reacts to DynamoDB Streams and pushes updates back out. Neither one runs — or costs anything — except when something actually triggers it.
DynamoDB
Stores the visitor count in one table and tracks which WebSocket connections are currently open in a second. DBUpdater writes to both; DBStreamProcessor separately reads the connections table to know who to push each update to.
DynamoDB Streams
Watches the visitor count table for writes, and is what actually links DBUpdater to DBStreamProcessor — every time DBUpdater increments the count, the stream fires and triggers DBStreamProcessor automatically, with no polling involved on either side.

Behind the scenes

Deploying and staying safe

IAM
Controls what every other piece here is actually allowed to do — which resources a given Lambda can read or write, what GitHub Actions is permitted to deploy. Every interaction between these services implicitly passes through an IAM permission check first.
CloudFormation / SAM
Defines the DynamoDB tables, both Lambda functions, and the API Gateway in one YAML template, deployed with a single command. This is exactly what GitHub Actions runs when it deploys the backend — nothing about the backend is ever clicked together by hand.
GitHub Actions
Deploys both halves of the project automatically on every push — syncing the frontend to S3 and invalidating CloudFront, or running the backend's tests and then deploying through SAM/CloudFormation, depending on which folder actually changed.
AWS Budgets
A cost safety net sitting outside the application itself — watches spending across every service above and sends an email alert if it crosses a threshold, so nothing here can run away unnoticed.

Architecture

How it fits together

The static site (left) and the visitor counter (right) are independent of each other — the counter could be swapped out entirely without touching the resume content itself. GitHub Actions deploys the two halves differently: the frontend syncs straight to S3, while the backend deploys through AWS CloudFormation, which is what actually provisions the Lambda functions, DynamoDB tables, and API Gateway from the SAM template.

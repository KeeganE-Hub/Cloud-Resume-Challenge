How it's built

Technical Breakdown

A plain-language rundown of every service this project uses, and what it's actually doing. If you're skimming this before an interview or a code review, this is the short version of each piece — the full story (including what broke along the way) is in the blog post.

Frontend delivery

Getting the site to a browser

S3
Amazon's file storage service. This is where the actual HTML, CSS, JS, and image files for the resume site live. It's not serving them directly to visitors, though — that's CloudFront's job.
CloudFront
a content delivery network (CDN). It sits in front of the S3 bucket, caches the site at edge locations around the world so it loads fast wherever a visitor is, and handles HTTPS for the domain. The S3 bucket itself stays private — only CloudFront is allowed to read from it.
Route 53
AWS's DNS service. It points the domain name at CloudFront, and it's also where the domain itself was registered.
Certificate Manager (ACM)
issues the free TLS certificate CloudFront uses to serve the site over HTTPS instead of plain HTTP.

The visitor counter

Where the number comes from

API Gateway
the entry point the browser actually talks to. This project uses two kinds side by side: a REST API (the original counter) and a WebSocket API (the real-time version) — they work quite differently under the hood even though they're the same underlying AWS service.
Lambda
the actual code that runs when a request comes in. No server to manage, and it only runs — and only costs anything — while it's handling a request. There are three functions here: one for the REST counter, and two for the WebSocket version.
DynamoDB
a NoSQL database. Here it stores exactly one number — the visitor count — plus, for the real-time version, a list of which WebSocket connections are currently open.
DynamoDB Streams
fires an event every time something changes in a table. The real-time counter is built around this: every time the count updates, the stream triggers a Lambda that pushes the new number out to every open connection.

Behind the scenes

Deploying and staying safe

IAM
controls who — or what — is allowed to do what in the AWS account. Every Lambda, every deploy, every API call goes through an IAM permission check.
CloudFormation / SAM
Infrastructure as Code. The entire backend is defined in one YAML template and deployed with a single command, so it can be rebuilt from scratch if it ever needs to be.
GitHub Actions
deploys the site automatically on every push — no touching the AWS console by hand.
AWS Budgets
a cost safety net. Sends an email alert if spending crosses a threshold, so nothing runs away unnoticed.

How it fits together
